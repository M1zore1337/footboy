## 本轮修复验证

### 比赛源直连

本地代理只转发 B 站音源夹具，拒绝比赛源的所有请求。未启用直连时，比赛源探测按预期失败；启用后，普通 HLS 和 AES-128 HLS 的探测、PyAV 关键帧采样及 FFmpeg 混流均成功，代理日志只出现 B 站请求。播放列表、分片和密钥请求继续携带测试 Cookie。

复现了空 `http_proxy` 选项只对首个播放列表有效、后续分片仍继承环境代理的问题。修复使用可传递到 HLS 子请求的非空直连选项，不修改进程全局代理环境。

两种 HLS 输入均验证采样 PTS 保持原值、输出音视频相对 PTS 误差不超过 25ms、视频解码像素与输入相同。原有正负偏移用例同时继续通过，对齐定义保持 `D = K_B - K_V`。

### FFmpeg 构建与异常退出

使用同一个本地合成 HLS 对照读取：此前使用的 `7.0.2-static` 构建返回 `-11 / SIGSEGV`，上表新构建返回 0。此结果针对本机这两个具体构建；没有据此判定所有 7.0.2 构建均不兼容。

新版 `N-…` 构建原本因没有正式主版本号而被环境检查拒绝。现在最低 FFmpeg 6 检查允许使用其运行时 libavformat 主版本（至少 60）确认兼容下限；旧库及无法确认的版本仍拒绝。

模拟原生崩溃验证：混流任务进入 ERROR，取消测量、保留偏移并停止自动重取源；控制台可再次连接。普通退出码 1 继续走取流恢复。ffprobe 崩溃显示程序异常诊断。Windows 异常退出码只做了模拟检查，未在 Windows 原生环境验收。
