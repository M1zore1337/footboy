# OCR 第二轮优化验证

日期：2026-09-13。基于第一轮提交 `97df6a5`，本机 Python 3.14、Tesseract 5.5.0。

## 改动

- 保存框与候选验证先检查每第三帧，已知缺失或跳变使连续三帧不再可能时提前淘汰。未知帧仍按可能有效处理，潜在连续停表也保留检查机会；成功区域仍读取完整序列，最终沿用原有走表、PTS、残差和停表判定。
- 保存框按原样式、其它后备样式重试，失败后先检查周边文字候选，最多尝试八个配置，再回退全画面。已尝试的相同配置不重复读取，不按重叠面积直接合并宽窄不同的裁剪。
- 新增 `adaptive` 后备样式，用局部背景校正、Otsu 和边距处理亮度不均的小字。标准及窄字优先级保留，旧配置继续默认使用标准样式。
- Tesseract 每次调用的超时取剩余预算与两秒中的较小值，调用返回后再次检查期限。自动发现根据已测调用耗时预留连续验证时间；取消优先于同次调用的超时，后端失败继续与需要框选区分。
- 网页增加无遮罩的当前选区预览、最近单帧读数、连续验证状态，以及实际试读裁剪、预处理图、原始文字和耗时。单路连续通过也不会自行应用两路偏移。图像接口需要控制密钥，并按本次读数版本返回图片。
- 测量进度与预览均检查设置修订、源代次和取消状态；新区域、手动偏移及新源不会被旧回调覆盖。网页也丢弃控制操作完成前发出、完成后才返回的旧状态响应。只有两路测量通过且仍有效时才保存自动锁定配置。
- 增加 `python -m footboy.tools.ocr_diagnose`，按需输出候选尝试顺序、图片、原始文字、耗时、淘汰原因和结果。目录必须不存在，自动写入 `.gitignore`；不打开直播、不修改状态文件。

离线诊断的两项测试在前两组重复执行；去重后共 **195 项通过**。其中 OCR 两份测试为 80 项，包括真实 Tesseract 的 24 项合成图集成测试。

新增覆盖八帧中全部 256 种有效/遮挡组合、不同位置的后三帧停表、后排候选可达性、首帧缓存包含零值、Tesseract 剩余预算传递、通用后端不接收专有参数、超时后禁止锁定，以及取消、旧预览、旧测量回调的隔离。

两个亮字/暗字合成序列使用 13 像素高的数字、低对比度和渐变背景。标准样式不能读取其首帧完整时间，新增后备样式均读出 `61:54 → 61:56 → 61:58 → 62:00`，四帧全保留，残差为零。原窄字体、四种翻转、宽间距冒号、亮底深字、倒计时干扰、停表及两路独立 PTS 测试保持通过。

新增的两项浏览器测试使用受控 OCR 状态，验证当前裁剪不含遮罩、`00:00` 显示、单帧与连续锁定的区别、错误分类、来源切换显示、编辑后清除旧反馈，以及保存后才返回的旧状态不会恢复旧区域或锁定提示。另三项已有浏览器测试使用本地合成媒体验证实际播放、保存区域、手动调整、音量、线路切换和停止。HTTP 与浏览器在允许本机套接字和 Chromium 运行的环境执行。

两版仍各测三次，使用相同输入与十五秒预算，全部通过。

离线诊断工具也对真实第一组四帧从错误保存框运行一次：十次调用，四帧全部通过，残差零。生成的 JSONL 包含候选优先级和淘汰原因，PNG 包含实际裁剪与预处理图；原始素材、诊断输出和浏览器截图均留在本地。

## 限制

真实素材仍只有同一场比赛的少量画面；小字亮度校正的新增场景为合成素材。本轮没有改变自动候选检测的全局亮度阈值及位置限制，不能据此推断所有低对比度时钟都能被自动定位。

Tesseract 使用原生单次超时，进程清理与诊断写入仍可能带来少量额外耗时。RapidOCR 等同步后端只在调用前后检查整体期限，不能在其内部强制中断；未安装 RapidOCR，本轮没有验证该引擎。显式交互框选的用户等待不占用框选后的验证预算；网页后台仍禁止隐式 GUI 或终端提示。

未重启现有 Footboy 服务，也未读取新的真实直播；新代码需在服务下次启动时加载。未验证真实双路同步、长时间运行、原生 Windows/macOS 或实体手机 Safari；没有重跑其它媒体集成和打包流程。
