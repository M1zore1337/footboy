## 复现的问题与修复

原有自动搜索主要依赖角落和画面中央的大块区域。视频样本 A 主计时位于顶部中央，数字本体仅约 24–26×13 像素；附近还有比分、经济数值以及倒计时。大块区域既会切开主计时，也会把相邻文字送入 Tesseract 的单行识别。

第一批抓取 7 个真实关键帧，源 PTS 相隔 3 秒。旧版自动识别未锁定；指定主计时 ROI 后，7 帧中仅一帧解析出时间，而且把 `04:53` 误读为 `04:33`。此前的 28 项 OCR/PTS 相关回归仍全部通过，表明原有清晰合成时钟没有覆盖这个场景。

修复包括：

- 在顶部、底部和中央搜索短文本行，形成避开相邻比分的紧凑 ROI；保留原有区域搜索，并补充顶部、底部中央。
- 保留标准识别方式，为细长亮色数字增加横向放大、亮度阈值及 Tesseract 原始单行识别作为备用方式。
- 手动或已保存 ROI 先在原位置尝试备用样式，成功后连同样式保存。旧配置缺少样式字段时沿用标准方式。
- 继续要求至少 3 帧连续走表、残差不超过 1 秒；保留预算、取消、停表判断及 `D = K_B - K_V`。视频和混流时间轴实现未改动。

## 单路复测方式

安装 Tesseract 和项目的 `tesseract` 可选依赖后，将房间地址放入本机环境变量 `FOOTBOY_BILI_ROOM_URL`，可直接调用现有采样与识别路径。Tesseract 不在 PATH 时，为 `TesseractBackend` 传入可执行文件路径。

```python
import os

from footboy.probe.frames import collect_keyframes
from footboy.probe.ocr import TesseractBackend, probe_clock
from footboy.sources.bili import BiliResolver

source = BiliResolver().resolve(os.environ["FOOTBOY_BILI_ROOM_URL"])
frames = collect_keyframes(source)
result = probe_clock(frames, TesseractBackend(), allow_manual=False)
print(result.config)
print([(sample.pts, sample.clock) for sample in result.samples])
print("K:", result.k, "residual:", result.residual)
```

房间必须开播且画面中有走动的比赛时钟；赛间、遮挡或无法连续识别时会明确失败。不要打印或提交解析后的签名媒体地址。

## 限制

- 本轮只覆盖该房间当时的非足球赛事重播布局。漏读和误读仍会发生，无法锁定时须框选或手动调整。
- 没有验收两个独立内容来源的同场足球同步精度、实际长延迟缓冲或连续两小时运行；同一路媒体的 D=0 不能替代这些检查。
- 当前 Python 3.14 环境使用 Tesseract，没有验证 RapidOCR。没有 Windows/macOS 原生环境、实体手机 Safari 或 HEVC 浏览器播放验收。
- 残差描述比赛时钟与源 PTS 的一致程度，不等同于真实听感或设备播放延迟的精度。
